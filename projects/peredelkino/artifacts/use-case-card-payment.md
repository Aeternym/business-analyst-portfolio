# UC-04 · Оплатить заказ банковской картой

> Фрагмент спецификации учебного проекта «Переделкино» (2026). Описывает проектируемый сценарий, а не действующую платёжную интеграцию.

| Поле | Значение |
| --- | --- |
| Уровень | Подфункция процесса оформления заказа |
| Основной актор | Покупатель |
| Внешний участник | Сервис онлайн-оплаты |
| Связанный сценарий | UC-03 «Оформить заказ» |
| Связанная история | US-11 «Информация об ошибке оплаты» |

## Предусловия

- Покупатель выбрал оплату банковской картой.
- Состав заказа проверен, товар зарезервирован.
- Итоговая стоимость рассчитана.

## Основной сценарий

1. Сайт запрашивает создание платёжной сессии во внешнем сервисе.
2. Сервис создаёт сессию и возвращает необходимые данные.
3. Покупателю открывается форма оплаты.
4. Покупатель вводит платёжные сведения и подтверждает операцию.
5. Платёжный сервис обрабатывает операцию и передаёт результат сайту.
6. При успешной оплате система устанавливает статус оплаты «Оплачено».
7. Пользователь видит подтверждение и получает чек, предусмотренный платёжным сервисом.
8. Управление возвращается к сценарию UC-03 «Оформить заказ».

## Альтернативные потоки и исключения

| Код | Ситуация | Реакция системы |
| --- | --- | --- |
| 2а | Не удалось создать платёжную сессию | Сообщить об ошибке; дать повторить попытку или сменить способ оплаты. |
| 6а | Платёж отклонён | Не устанавливать статус «Оплачено»; предложить повторить платёж. |
| 6б | Пользователь выбирает другой способ | Вернуть к выбору способа оплаты. |
| 6в | Пользователь отказывается от оформления | Не отмечать заказ как оплаченный; освободить резерв согласно процессу. |

## Проверяемые условия

- Неуспешная операция не переводит оплату в успешный статус.
- Покупатель может повторить платёж или сменить способ оплаты.
- Платёжные реквизиты обрабатываются внешним платёжным сервисом, не хранятся интернет-магазином.
